Design principles by HIG subpage

This reference separates the HIGDesign design system by HIG subpage, adds generated visual snapshots, and links each page back to Apple's official Human Interface Guidelines. It is intentionally paraphrased and HIGDesign-specific.

How code agents should use this

Start with the subpage that matches the UI change, apply the HIGDesign interpretation and review questions, then verify the official Apple HIG page for final platform nuance.

Foundations

Foundations

Accessibility

Every interaction needs a clear label, readable text, adequate contrast, Dynamic Type behavior, and VoiceOver-friendly structure.

Dynamic TypeVoiceOverLabels

Branding

Brand expression should support platform clarity instead of overwhelming native controls.

IdentityNative

Color

Use semantic, adaptive color. Do not use color as the only status signal.

SemanticContrast

Dark Mode

Surfaces, text, separators, and materials must adapt cleanly between light and dark appearances.

AppearanceSystem colors

Feedback

Make state changes visible and understandable without noisy interruption.

StateErrors

Layout

Use hierarchy, alignment, spacing, and adaptive containers to keep content scannable.

AdaptiveSpacing

Materials

Use platform materials to separate chrome and content when the platform expects it.

SystemSidebar

Motion

Motion should clarify transitions and respect Reduce Motion.

Reduce MotionTransitions

Privacy

Ask only for necessary access and explain user value in user-facing language.

LoggingPermissions

SF Symbols

Use system symbols for common actions and match symbol weight to surrounding text.

IconsToolbar

Typography

Use dynamic text styles and a clear hierarchy instead of fixed viewport-scaled type.

Text stylesHierarchy

Writing

Write concise labels, buttons, and errors that state what happened and what the user can do next.

CopyErrors

PermissionsPrivacy

ShareVisibility

FormValidation

AccountSettings

NotificationsSettings

SheetPopoverInspector

Ask for ratings respectfully and never block workflows.

RatingStoreKit

Searching

Search should be easy to find, scoped clearly, and integrated with platform behavior.

searchableFilters

Settings

Settings should contain durable preferences, not primary workflows.

PreferencesAccount

Support reversal for editing and destructive local changes where practical.

EditingSafety

Buttons

Buttons need clear labels or familiar symbols, appropriate prominence, and disabled/loading states.

ButtonRole

Menus

Menus group related commands and choices without crowding the surface.

MenuCommands

Pop-up buttons

Toolbars

Toolbars hold frequent screen-level actions and navigation-adjacent commands.

ToolbarItemCommands

Sidebars

NavigationSplitView

searchableScope
