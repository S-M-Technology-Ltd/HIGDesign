HIGDesign HIG/Components

Components

Split views

Split views support browsing and editing without losing context.

HIGDesign interpretation

Default for iPad/macOS library, community detail, following feed, and admin review.

Must do

  • Prefer native SwiftUI components before wrappers or custom controls.
  • Add accessibility labels for icon-only or ambiguous controls.
  • Validate the component in compact and regular layouts.

Avoid

  • Do not wrap native controls unless it removes real duplication.
  • Do not create custom control behavior without accessibility review.
  • Do not put application business logic inside design-system components.

SwiftUI references

  • NavigationSplitView

HIGDesign review questions

  • Which HIGDesign workflow or surface uses this principle?
  • Does the implementation use native SwiftUI before custom UI?
  • Does it behave correctly on iOS, iPadOS, macOS, visionOS, tvOS, and watchOS where applicable?
  • Are empty, loading, error, disabled, and success states represented where needed?
  • Does the component avoid logging user-entered text, secrets, or private app content?
